
# Платформа обработки и аналитики судебных документов

Проект автоматизированной обработки судебных и исполнительных документов с использованием OCR, локальной LLM и инструментов Data Engineering.

Первоначально система была разработана в рамках хакатона **«ИИ-ассистенты для энергетики»** в треке **«Помощник для анализа документов из судов (OCR и извлечение данных)»**.

В рамках хакатона была создана система для загрузки PDF/XML, распознавания текста, извлечения реквизитов, классификации документов и работы с результатами через веб-интерфейс.

**При дальнейшем развитии проекта основной акцент был сделан на Data Engineering:** организацию хранения и обработки данных, автоматизацию аналитических задач, проверки качества данных и построение аналитических витрин.

Проект объединяет обработку неструктурированных документов и работу с данными — от загрузки исходного файла до формирования аналитических показателей.

## О проекте

Система позволяет загружать судебные документы, извлекать из них необходимые данные и просматривать результаты обработки.

Основные возможности:

- Загрузка PDF и XML.
- Распознавание текста из сканированных документов.
- Извлечение реквизитов с помощью локальной LLM.
- Классификация документов.
- Сохранение результатов в PostgreSQL.
- Хранение исходных файлов в MinIO.
- Автоматические проверки качества данных.
- Формирование аналитических таблиц с помощью dbt.
- Запуск аналитических задач через Apache Airflow.
- Веб-интерфейс для просмотра и проверки документов.
- Экспорт результатов в XLSX/CSV.

## Архитектура проекта

Основной процесс обработки документов:

```text
          PDF / XML
              |
              v
            FastAPI
              |
        +-----+-----+
        |           |
        v           v
      MinIO      PostgreSQL
    (файлы)      (задания)
                    |
                    v
             Processing Worker
                    |
                    v
               OCR / LLM
                    |
                    v
                PostgreSQL
            (результаты обработки)
                    |
                    v
               Data Quality
                    |
                    v
                   dbt
                    |
                    v
                PostgreSQL
           (аналитические витрины)
                    |
                    v
                BI / DataLens
```

Для обработки документов используется отдельный Python Worker, который получает задания из PostgreSQL.

Аналитическая часть автоматизирована с помощью Apache Airflow.

## Обработка документов

### Загрузка данных

Пользователь загружает PDF или XML через веб-интерфейс.

После загрузки:

1. Проверяется формат документа.
2. Исходный файл сохраняется в MinIO.
3. В PostgreSQL создаётся запись о документе.
4. Документ добавляется в очередь на обработку.

### Извлечение данных

Обработка выполняется отдельным Python Worker.

Он получает документ, извлекает текст и использует локальную LLM для получения структурированных данных.

Для сканированных PDF применяется OCR.

В зависимости от типа документа система извлекает:

- ФИО должника.
- ИНН и СНИЛС.
- Номер судебного дела.
- Даты документов.
- Суммы задолженности.
- Другие необходимые реквизиты.

Результаты сохраняются в PostgreSQL.

### Обработка ошибок

В системе предусмотрены статусы обработки документов и повторные попытки при возникновении ошибок.

Это позволяет отслеживать, какие документы обработаны успешно, а какие требуют дополнительной проверки.

## Хранение данных

Основная база данных проекта — **PostgreSQL**.

В ней хранятся:

- Информация о документах.
- Извлечённые реквизиты.
- Результаты обработки.
- Статусы документов.
- История обработки.
- Данные для аналитики.

Исходные PDF/XML хранятся отдельно в **MinIO**.

Такой подход позволяет разделить работу с файлами и структурированными данными.

## Data Quality

Для проверки качества данных в проекте реализованы автоматические проверки на Python.

Они помогают находить:

- Дубли документов.
- Отсутствующие обязательные поля.
- Некорректные статусы.
- Ошибки в денежных значениях.
- Некорректные даты.
- Ошибки в реквизитах.
- Проблемы с результатами обработки.

Всего реализовано **13 проверок качества данных**.

Проверки запускаются перед обновлением аналитических витрин.

При обнаружении критических ошибок аналитический пайплайн останавливается.

## dbt и аналитические витрины

Для подготовки аналитических данных используется **dbt**.

Данные из PostgreSQL преобразуются в модели, которые затем используются для анализа обработки документов.

В проекте выделены несколько уровней:

- **Staging** — подготовка исходных данных.
- **Intermediate** — объединение и преобразование данных.
- **Data Marts** — итоговые таблицы для аналитики.

Основные аналитические витрины:

| Витрина | Назначение |
|---|---|
| `mart_document_processing_daily` | Статистика обработки документов по дням |
| `mart_document_quality` | Показатели качества данных |
| `mart_document_types` | Распределение документов по типам |
| `mart_legal_actions` | Документы, требующие юридических действий |

Аналитические витрины сохраняются в PostgreSQL.

С их помощью можно анализировать количество документов, ошибки обработки, качество извлечения и общую динамику работы системы.

## Apache Airflow

Для автоматизации аналитической части проекта используется **Apache Airflow**.

В проекте создан DAG `document_analytics_pipeline`, который последовательно выполняет две основные задачи:

1. Запускает проверки качества данных на Python.
2. Обновляет аналитические модели через dbt.

```text
Data Quality
     |
     v
    dbt
     |
     v
Аналитические витрины
```

Пайплайн настроен на ежедневный запуск.

## BI-аналитика

Для визуализации аналитических показателей в проекте использовался **Yandex DataLens**.

Дашборд позволяет анализировать:

- Количество обработанных документов.
- Распределение документов по типам.
- Статусы обработки.
- Ошибки и качество извлечения.
- Документы, требующие ручной проверки.
- Динамику обработки документов.

После упрощения архитектуры аналитические витрины формируются непосредственно в PostgreSQL. Подключение ранее созданного дашборда к обновлённому источнику требует отдельной проверки.

## Веб-интерфейс

Для работы с документами разработано веб-приложение на **React и TypeScript**.

Интерфейс позволяет:

- Загружать документы.
- Просматривать журнал документов.
- Отслеживать статусы обработки.
- Открывать карточки документов.
- Просматривать извлечённые реквизиты.
- Исправлять и подтверждать данные.
- Работать с документами на ручной проверке.
